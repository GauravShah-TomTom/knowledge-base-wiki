# No Rule-to-Transaction Tracing in Iris

## Summary

After the [[Lanes]] pipeline creates transactions and sends them to [[Iris]], there is no way for editors to filter and see *only* the transactions that were generated by a specific [[DTFR]] rule fix. This makes targeted QA (calculating precision and recall for a specific rule) difficult because rule-specific transactions are mixed with all other transactions.

## Planned solution

The pipeline will be extended to:
1. Populate rule metadata in the [[Lanes Automator]] output JSON (which [[DTFR]] rule was applied).
2. Use that metadata in [[Transaction Manager]] when calling the [[Iris]] API — set priority = 1 for rule-specific transactions, priority 2–3 for others.
3. Editors can then filter Iris by priority to surface rule-impacted transactions.

Decision: [[decisions/Use Iris Priority Field for Rule-Specific Transactions]]

## Alternative considered

Creating a separate Iris project per rule ID was proposed by [[Gaurav Shah]] but rejected because a single transaction can involve multiple rules simultaneously.
