# Decision: Use Iris Priority Field to Tag Rule-Specific Transactions

## Context

After fixing the top DTFR rule issues in [[Lanes]], the team needs editors in [[Iris]] to verify the generated transactions — specifically the ones affected by the rule changes — to calculate precision and recall. The challenge: transactions from multiple rules are mixed together in Iris, and there is no automatic way to separate "changed by a new rule" transactions from background transactions.

Options considered:
1. **Create a separate Iris project per rule ID** — rejected as too complex; a transaction might belong to multiple rules simultaneously.
2. **Use the Iris priority field** — set priority 1 for transactions generated by a default/DTFR rule, priority 2–3 for others. Editors can filter by priority 1 to verify rule-specific transactions first, then sample the rest.

## Decision

Use the **Iris priority field** to distinguish rule-specific transactions. The [[Lanes Automator]] / [[Transaction Manager]] pipeline will:
1. Populate rule metadata in the output JSON (rule ID already tracked).
2. When sending tasks to Iris, set priority = 1 for transactions where a [[DTFR]] default rule was applied; priority 2–3 otherwise.

Editors filter on priority to focus QA on the impacted transactions.

## Rationale

Simple to implement (one metadata field), does not require separate Iris projects, and allows editors to independently choose their review order.
